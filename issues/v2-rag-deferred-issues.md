# V2 RAG 待处理问题

本文记录 V2 代码审查中确认存在、但当前阶段暂缓处理的问题。

## 1. 分批写入失败可能留下部分索引

状态：暂缓处理

### 当前行为

`ChromaVectorStore._upsert_chunks()` 每 100 个 Chunk 写入一批。如果前面的批次已经
成功，而后续批次失败，上传接口会返回 HTTP 500，但已经写入的部分向量仍可能留在
Chroma 中并参与后续检索。

### 影响

- RAG 可能检索到上传失败文档的不完整内容。
- 重新索引失败时，collection 可能同时包含新旧索引数据。

### 后续方案

- 简单方案：写入失败时删除该 `document_id` 的所有向量。
- 完整方案：使用临时版本写入，所有批次成功后再切换为有效版本。
- 增加一个模拟第二批写入失败的测试，确认失败索引不会被查询到。

### 验收标准

- 索引失败后，该次不完整索引不可被检索。
- 成功重新索引后，不残留旧 Chunk。

## 2. Qdrant 配置与实际实现不一致

状态：暂缓处理

### 当前行为

`Settings.vector_store` 接受 `chroma` 和 `qdrant`，但 V2 始终实例化
`ChromaVectorStore`。设置 `VECTOR_STORE=qdrant` 时，程序仍会使用 Chroma。

### 影响

- 配置会被静默忽略。
- 使用者可能误以为向量已经写入 Qdrant。

### 后续方案

- 在只支持 Chroma 时，将配置限制为 `Literal["chroma"]`，并移除或注释未启用的
  Qdrant 配置。
- 开始支持多个向量数据库后，增加 vector store factory，根据配置创建对应实现。

### 验收标准

- 配置声明的 vector store 与运行时实现一致。
- 未实现的 provider 会在应用启动时给出明确错误，不再静默回退。
